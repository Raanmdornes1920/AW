Detalles del proyecto: BISTRO FDI

Introducción

BISTRO FDI es una aplicación web pensada para facilitar la experiencia de comedor/cafetería dentro del entorno de la FDI. El objetivo es que los usuarios puedan consultar la oferta disponible (platos, menús o productos), ver información relevante (ingredientes, alérgenos, precio y disponibilidad) y realizar acciones asociadas al servicio sin depender de comunicación presencial.

El sistema busca mejorar la organización y reducir tiempos de espera, permitiendo a los usuarios tomar decisiones con antelación. Además, ofrece herramientas de gestión para el personal encargado, de forma que puedan mantener actualizado el catálogo y controlar la operativa diaria.

Tipos de usuarios

  • Visitante (no registrado): puede acceder a la página principal y consultar información pública como la presentación del servicio, la carta/menús y datos básicos de contacto.
  • Usuario registrado: puede iniciar sesión y acceder a funcionalidades personalizadas como marcar productos como favoritos, guardar preferencias (por ejemplo, alérgenos) y realizar la acción principal del sistema (según el diseño del grupo: reserva/pedido/precompra/consulta avanzada).
  • Administrador / personal de gestión: puede crear, editar o eliminar platos/productos, actualizar precios y disponibilidad, y moderar o revisar información asociada al contenido.

Funcionalidades

  • Explorar carta/menús: visualización de platos o productos disponibles con precio y descripción. (Visitante y registrado)
  • Información de alérgenos e ingredientes: cada elemento muestra datos relevantes para personas con intolerancias o preferencias. (Visitante y registrado)
  • Búsqueda y filtrado: búsqueda por nombre y filtros por tipo, precio o alérgenos. (Visitante y registrado)
  • Detalle de producto/plato: página con información completa, imagen y botones de acción. (Visitante y registrado)
  • Registro e inicio de sesión: acceso mediante credenciales para habilitar funciones personalizadas. (Registrado)
  • Favoritos o lista personal: guardar elementos preferidos para consultarlos rápidamente. (Registrado)
  • Acción principal del sistema: realizar un pedido/reserva/preparación (según el diseño elegido) y obtener confirmación. (Registrado)
  • Gestión del catálogo: alta, baja y edición de platos/productos, con control de disponibilidad. (Administrador)

Nota: la práctica implementa una versión estática en HTML que documenta el diseño y la navegación del sistema.
